# SOP Writing Guide

## Write for the person doing the work

Provide enough context to perform the process without burying actions in
unnecessary prose.

## Use observable actions

Prefer `Record the request in [SYSTEM]` over vague statements such as
`Requests should be appropriately dealt with.`

## Name responsibility

When multiple roles participate, state who performs an action or makes a
decision.

## Keep sequence visible

Number procedural steps and place prerequisites before the procedure.

## Document decisions

Write the condition and response clearly:
`If the required approval is missing, stop processing and send the item to [ROLE].`

## Separate procedure from policy

Reference authoritative policies instead of casually creating new
organizational rules inside an SOP.

## Treat exceptions deliberately

Document common exceptions. Use escalation for unusual or judgment-heavy
situations.

## Be careful with records

State what record is created and where it belongs. Only state retention
periods when they come from an authoritative requirement applicable to
the organization.

## Test before release

Have someone familiar with the work walk through the draft and identify
missing assumptions, unclear handoffs, or outdated steps.

## Keep it maintainable

Use role names where practical. Avoid fragile detail that will make the
SOP obsolete unnecessarily.
